## Summary

Deliver permission, role, and user administration with role-permission editing and user role
assignment for a server-rendered admin console. The feature implements the five-entity RBAC
model (Users, Roles, Permissions, Role-Permissions, User-Roles) under a fail-closed,
permission-enforced Spring Security pipeline, with lockout-protection guardrails around the
protected Super Admin role, centralized permission identifiers, Jakarta Bean Validation on
all mutations, and dual-sided authorization tests. Full design decisions in
[research.md](research.md); interface contracts in [contracts/](contracts/README.md); data
model in [data-model.md](data-model.md).

## Technical Context

**Language/Version**: Java 21 (`<java.version>21</java.version>` in `pom.xml`; satisfies
constitution Principle III "Java 17 LTS or newer")

**Primary Dependencies**: Spring Boot 4.1.1 (web, thymeleaf, validation, data-jpa, security),
Hibernate ORM, H2 Database (embedded), Thymeleaf with CoreUI Admin Bootstrap 5 template,
Lombok, Spring Boot Test + spring-security-test (testing)

**Storage**: Embedded H2, schema generated by Hibernate (`ddl-auto`); idempotent
application-level seed data. PostgreSQL removed per constitution v2.0.0; persistent DB
deferred.

**Testing**: JUnit 5 + MockMvc with spring-security-test; parameterized dual-sided
authorization suite (200 for permitted, 403 for unauthorized), guardrail tests (409), audit
assertions.

**Target Platform**: Server-rendered admin web application; standard desktop web browsers.

**Project Type**: Web application (admin console)

**Performance Goals**: Reportedly SC-001/SC-002 target times (5-min full setup, 2-min role
assignment) — UI-level, not throughput; standard web-app responsiveness (<2s per screen
under normal usage).

**Constraints**: Fail-closed security; middleware permission resolution before controllers;
Java Bean Validation on every mutation; UUID (v4) PKs; strict FKs + cascade teardown;
lockout guardrails (G1/G2/G3); centralized permission codes; UTC timestamps; dual-sided
authorization tests mandatory.

**Scale/Scope**: Single organization; small-to-mid admin population (tens to low hundreds);
five core tables + supporting audit log.

**Structure Decision**: Single Spring Boot Maven project rooted at the repository root
(`com.allensandiego.adm`, artifact `adm`). Server-rendered (Thymeleaf + CoreUI) means there is
no separate frontend build; one deployable with the security layer co-located with the
controllers. The upstream CoreUI template is vendored in `coreui/` and its CSS/JS are served
from `src/main/resources/static/`. Feature slices (permission → role → user) map to
controller/service packages ordered by dependency (data-model.md).
